# 미팅 노트 기능 요구사항

- 작성일: 2026-11-24
- 상태: 확정 (2026-11-24 질의응답 반영)
- 관련 화면: 헤더 메뉴, 미팅 노트 페이지, 리드 상세(LeadModal)

## 1. 배경 / 목적

영업 담당자는 리드와 미팅을 한 뒤 내용을 따로 메모하거나 기억에 의존하고 있다.
미팅 내용을 **리드에 연결된 기록**으로 CRM 안에 남겨, 리드를 열면 지금까지의 미팅 히스토리를 바로 볼 수 있게 한다.

## 2. 범위

| 포함 (이번 작업) | 제외 (추후 검토) |
|---|---|
| 상단 메뉴에 `미팅 노트` 추가 | 화상회의 도구(Zoom, Meet) 연동 |
| 미팅 노트 리스트 / 작성 / 수정 / 삭제 | 화면(영상) 녹화 |
| 노트 작성 시 **음성 녹음 → GPT transcribe 전사** (최대 60분, 구간 분할) | 녹음 파일 원본 보관·재생 |
| 노트 작성 시 **복사·붙여넣기**로 직접 입력 | 화자 분리, 실시간 자막 |
| 노트 ↔ 리드 연결, 리드 상세에서 노트 리스트 표시 | 리드 없는 노트 |
| **AI 요약·다음 액션** 생성 | |
| **AI Assistant가 미팅 노트를 참고**해 답변 | |

## 3. 용어

- **미팅 노트(Meeting Note)**: 특정 리드와의 미팅 1건에 대한 기록. 제목, 미팅 일시, 본문, 연결된 리드로 구성.
- **녹음 입력**: 브라우저 마이크로 미팅을 녹음하고, 녹음이 끝나면 음성을 텍스트로 변환해 본문에 넣는 방식.
- **붙여넣기 입력**: 다른 도구(회의록, 메신저, 자동 자막 등)의 텍스트를 본문에 붙여넣는 방식.

## 4. 기능 요구사항

### 4.1 메뉴

- FR-1. 헤더에 메뉴 탭 `파이프라인` / `미팅 노트`를 추가한다. 현재 칸반 보드는 `파이프라인` 메뉴가 된다.
- FR-2. 선택한 메뉴는 활성 상태로 표시하고, URL로도 구분한다 (예: `/`, `/meetings`). 새로고침해도 같은 메뉴가 유지된다.
- FR-3. 검색창, 테마 전환, AI Assistant 버튼은 두 메뉴에서 공통으로 유지한다. `새 리드` 버튼은 `미팅 노트` 메뉴에서는 `노트 작성` 버튼으로 바뀐다.

### 4.2 미팅 노트 리스트

- FR-4. 전체 미팅 노트를 **미팅 일시 최신순**으로 보여준다.
- FR-5. 각 항목 표시 정보: 제목, 미팅 일시, 연결된 리드(회사명 + 단계 배지), 본문 앞부분 미리보기(2줄), 입력 방식 아이콘(녹음/붙여넣기).
- FR-6. 헤더 검색창으로 제목·본문·회사명을 검색한다.
- FR-7. 리드별 필터(드롭다운)를 제공한다.
- FR-8. 노트가 없으면 빈 상태 안내와 `노트 작성` 버튼을 보여준다.
- FR-9. 항목을 클릭하면 노트 상세(보기/수정) 화면이 열린다.

### 4.3 노트 작성

- FR-10. `노트 작성`을 누르면 작성 화면(모달)이 열린다. 입력 항목:
  - 연결 리드 (필수, 리드 검색 선택)
  - 제목 (필수, 기본값: `{회사명} 미팅`)
  - 미팅 일시 (필수, 기본값: 현재 시각)
  - 본문 (필수, 여러 줄 텍스트)
- FR-11. 본문 입력 방식으로 **녹음하기**와 **직접 입력/붙여넣기** 두 가지를 제공한다. 두 방식은 섞어 쓸 수 있다 (녹음 결과를 붙여넣은 텍스트 뒤에 추가 등).

#### 녹음하기

- FR-12. `녹음 시작` 버튼을 누르면 브라우저 마이크 권한을 요청하고 녹음을 시작한다.
- FR-13. 녹음 중에는 경과 시간, 녹음 중 표시, `일시정지` / `재개` / `녹음 종료` 버튼을 보여준다.
- FR-14. 녹음은 **약 2분 단위 구간**(2026-11-26 5분 → 2분: 화자 구분 전사가 Vercel 함수 시간 60초를 넘겨 실패)으로 나눠 처리한다. 구간이 끝날 때마다 해당 음성을 서버로 보내 전사하고, 결과를 순서대로 본문 끝에 이어 붙인다. 녹음 중에도 앞 구간의 전사 결과가 본문에 나타난다.
- FR-14a. 녹음 종료 시 마지막 구간을 전사한다. 전사 중에는 "전사 중 (n/m 구간)" 진행 상태를 표시하고, 다른 입력은 계속 가능하다.
- FR-14b. 특정 구간 전사가 실패하면 해당 구간만 `다시 시도`할 수 있게 한다. 전사가 모두 끝나기 전에 저장하려 하면 확인 창을 띄운다.
- FR-15. 변환된 텍스트는 저장 전 사용자가 자유롭게 수정할 수 있다.
- FR-16. 최대 녹음 시간은 **60분**으로 한다. 종료 5분 전에 안내하고, 도달하면 자동 종료 후 마지막 구간을 전사한다.
- FR-17. 마이크 권한 거부, 미지원 브라우저, 변환 실패 시 한국어 에러 메시지를 보여주고 붙여넣기 입력은 그대로 사용할 수 있게 한다.
- FR-18. 녹음 시작 전 "참석자에게 녹음 사실을 알리세요" 안내 문구를 표시한다.

#### 잠금 화면 (2026-11-24 추가, 실시간 자막은 같은 날 제거)

- ~~FR-18a. 실시간 자막~~ — 2026-11-24 제거 (Realtime 전사·임시 키 API·관련 코드 삭제). 본문은 5분 구간 전사로만 채운다.
- ~~FR-18b. 구간 전사 실패 시 실시간 자막으로 대체~~ — 실시간 자막과 함께 제거. 실패 구간은 `다시 시도`만 제공.
- FR-18c. 화면 잠금·앱 전환으로 마이크가 끊기면 끊기기 전까지 녹음한 구간을 보존·전사하고, 화면으로 돌아오면 자동으로 녹음을 이어간다. 자동 재개가 막히면 `녹음 재개` 버튼을 보여주고, 녹음되지 않은 시간을 안내한다.
- FR-18d. 웹 브라우저(특히 iPhone)는 잠금 화면에서 마이크를 유지할 수 없으므로, 잠금 중 녹음이 필요하면 휴대폰 녹음 앱 파일(m4a·mp3·wav 등, 최대 90분)을 업로드해 전사한다. 파일은 브라우저에서 약 2분 단위 WAV로 나눠 구간 전사한다.

#### 다중 화자 구분 (2026-11-24 추가)

- FR-18e. 본문 전사(5분 구간·파일 업로드)는 화자를 구분해 `화자 1: …`, `화자 2: …` 형식으로 넣는다 (`gpt-4o-transcribe-diarize`, `diarized_json`). 실시간 자막은 화자 구분을 지원하지 않는다.
- FR-18f. 구간을 따로 전사해도 같은 사람이 같은 이름을 갖도록, 처음 나온 화자의 2~8초 음성을 참조(known_speaker_references, 최대 4명)로 다음 구간에 함께 보낸다. 5번째 화자부터는 구간마다 이름이 달라질 수 있다.
- FR-18g. 녹음 화면에서 화자 이름을 바꾸면(예: 화자 1 → 김민수) 본문의 기존 이름과 다음 구간 인식 이름에 반영된다.
- 제약: `gpt-4o-transcribe-diarize`는 2027-02-26 지원 종료 예정. 업로드 한도를 지키려고 녹음 구간 최대 3MB, 파일 구간 약 1분 30초로 줄였다.

#### 복사·붙여넣기

- FR-19. 본문 텍스트 영역에 직접 입력하거나 붙여넣을 수 있다. 붙여넣은 텍스트의 줄바꿈은 유지한다.
- FR-20. 본문 최대 길이는 50,000자로 제한하고, 남은 글자 수를 표시한다.

#### AI 요약·다음 액션

- FR-20a. 작성/상세 화면에 `AI 요약` 버튼을 둔다. 누르면 본문을 OpenAI로 보내 다음을 생성한다:
  - 요약 (3~5줄)
  - 고객 니즈/이슈
  - 다음 액션 (체크리스트, 담당·기한이 언급되면 포함)
- FR-20b. 생성 결과는 본문과 별도 필드(`summary`, `nextActions`)에 저장되며, 사용자가 수정할 수 있다. 다시 생성하면 덮어쓰기 전에 확인한다.
- FR-20c. ~~녹음 전사가 모두 끝나면 `AI 요약 생성` 안내만 표시~~ → (2026-11-24 변경) 미팅(녹음·파일 전사)이 끝나 자동 저장되면 **AI 요약·다음 액션을 자동 생성**한다. 서버(`POST /api/meetings/[id]/summarize`)가 요약을 저장하므로 작성 화면을 닫아도 완료된다. 요약이 비어 있거나 이전 자동 요약 그대로일 때만 실행하고, 사용자가 고친 요약은 덮어쓰지 않는다.
- FR-20d. 리스트와 리드 상세의 노트 항목은 요약이 있으면 본문 대신 요약을 미리보기로 보여준다.

### 4.4 노트 상세 / 수정 / 삭제

- FR-21. 상세 화면에서 제목, 미팅 일시, 연결 리드, 본문 전체, 작성·수정 시각을 보여준다.
- FR-22. 모든 항목을 수정할 수 있다 (연결 리드 변경 포함).
- FR-23. 삭제 시 확인 창을 띄운다.
- FR-24. 연결 리드를 클릭하면 해당 리드 상세가 열린다.

### 4.5 리드와 연결

- FR-25. 미팅 노트는 리드 1개에 연결된다. 단, 리드 없이도 저장할 수 있고(리드 미지정) 나중에 리드를 지정·변경할 수 있다. 리드 미지정 노트는 목록에 "리드 미지정" 표시와 필터를 제공한다. (2026-11-24 변경)
- FR-25a. 녹음(또는 파일 업로드) 전사가 모두 끝나면 리드가 없어도 노트를 자동 저장하고, 작성 화면은 수정 모드로 남아 리드를 지정할 수 있다. 리드 미지정 노트의 기본 제목은 "{날짜} 미팅".
- FR-25b. 리드 이력(lead_events)은 리드에 연결된 노트만 남긴다. 리드를 나중에 연결하거나 바꾸면 연결된 리드(및 이전 리드)에 note_updated를 기록한다.
- FR-26. 칸반에서 리드 카드를 클릭하면 열리는 리드 상세(LeadModal)에 **미팅 노트 섹션(탭)** 을 추가해, 해당 리드의 노트 리스트를 최신순으로 보여준다.
- FR-27. 리드 상세의 노트 섹션에서 바로 `노트 작성`을 할 수 있으며, 이때 연결 리드는 현재 리드로 고정된다.
- FR-28. 리드 카드에 미팅 노트 개수를 작은 배지로 표시한다 (0개면 표시하지 않음).
- FR-29. 리드를 삭제하면 연결된 미팅 노트도 함께 삭제된다. 리드 삭제 확인 창에 "미팅 노트 N개도 함께 삭제됩니다"를 표시한다.

### 4.6 AI Assistant 연동

- FR-30. AI Assistant가 미팅 노트를 참고해 답한다 (예: "A사와 지난 미팅에서 뭐가 이슈였어?", "이번 주 미팅한 리드의 다음 액션 정리해줘").
- FR-31. 컨텍스트에는 노트의 리드·제목·미팅 일시·요약·다음 액션을 우선 넣고, 질문에 특정 리드가 언급되면 해당 리드 노트의 본문도 포함한다. 토큰 한도를 넘지 않도록 최근 노트부터 길이 제한을 둔다.
- FR-32. 노트 본문에 포함된 이메일·전화번호는 OpenAI로 보내기 전 마스킹한다 (기존 Assistant 규칙 유지).
- FR-33. Assistant는 조회 전용이며 노트를 생성·수정하지 않는다.

## 5. 비기능 요구사항

- NFR-1. 기존 패턴을 따른다: Route Handler(`app/api/meetings/...`) + 클라이언트 훅(`useMeetings`), 낙관적 업데이트 → 실패 시 `reload()` + 에러 배너.
- NFR-2. 모든 입력은 `lib/validate.ts`로 검증하고, SQL은 파라미터 바인딩만 사용한다.
- NFR-3. 노트 생성·수정·삭제는 같은 트랜잭션에서 `lead_events`에 이력을 남긴다 (예: `note_created`, `note_updated`, `note_deleted` 타입 추가).
- NFR-4. 새 테이블은 RLS를 켜고 `crm_app` 전용 정책을 둔다.
- NFR-5. 스타일은 `globals.css`의 CSS 변수만 사용하고 라이트/다크 테마 모두 지원한다.
- NFR-6. 음성 전사는 **OpenAI GPT transcribe 모델**(`gpt-*-transcribe` 계열, `POST /v1/audio/transcriptions`)을 사용한다. 기존 AI Assistant와 같이 SDK 없이 `fetch`로 호출하고, 키는 기존 `OPENAI_API_KEY`를 사용한다. 모델은 `OPENAI_TRANSCRIBE_MODEL` 환경 변수로 변경 가능하게 하고, 기본값은 구현 시 OpenAI 문서에서 최신 모델명을 확인해 정한다. 언어 힌트는 한국어(`ko`)로 지정한다.
- NFR-7. 녹음 원본 파일은 전사 후 서버에 저장하지 않는다 (메모리에서만 처리, 텍스트만 저장).
- NFR-7a. AI 요약은 기존 Assistant와 같은 채팅 모델(`OPENAI_MODEL`, 기본 `gpt-6-luna`)을 사용한다. 요약 요청 시에도 이메일·전화번호는 마스킹한다.
- NFR-8. 새 패키지 없이 브라우저 기본 `MediaRecorder` API로 녹음한다.
- NFR-9. **반응형**: 640px 이하(모바일)에서는 아래처럼 배치한다 (와이어프레임 `wireframe.html?mobile` 참고).
  - 헤더: 로고·아이콘 / 메뉴 탭(가로 전체) / 검색창 3줄 구성, `노트 작성`·`새 리드`는 오른쪽 아래 ＋ 플로팅 버튼
  - AI Assistant: 오른쪽 패널 대신 하단 바 → 누르면 전체 화면 시트
  - 모달(노트 작성·상세, 리드 상세): 전체 화면, 헤더·하단 버튼 고정, 2열 입력은 1열
  - 칸반: 단계 컬럼 좌우 스와이프 (한 화면에 한 단계)
  - 녹음 버튼은 큰 터치 영역, 녹음 중 화면 꺼짐 방지(Wake Lock) + "화면을 켜 두세요" 안내 (모바일은 화면이 꺼지면 녹음이 끊길 수 있음)

## 6. 데이터 모델 (안)

```sql
CREATE TABLE IF NOT EXISTS meeting_notes (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  lead_id     uuid NOT NULL REFERENCES leads(id) ON DELETE CASCADE,
  title       text NOT NULL CHECK (length(trim(title)) > 0),
  met_at      timestamptz NOT NULL DEFAULT now(),
  body        text NOT NULL DEFAULT '' CHECK (length(body) <= 50000),
  source      text NOT NULL DEFAULT 'manual' CHECK (source IN ('manual','recording','mixed')),
  summary     text NOT NULL DEFAULT '',            -- AI 요약 (사용자 수정 가능)
  next_actions text NOT NULL DEFAULT '',           -- AI 다음 액션 (줄 단위 체크리스트)
  created_at  timestamptz NOT NULL DEFAULT now(),
  updated_at  timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS meeting_notes_lead_idx ON meeting_notes (lead_id, met_at DESC);
CREATE INDEX IF NOT EXISTS meeting_notes_met_at_idx ON meeting_notes (met_at DESC);
ALTER TABLE meeting_notes ENABLE ROW LEVEL SECURITY;
```

## 8. 제약 / 리스크

- **업로드 크기**: Vercel 함수 요청 본문 한도(약 4.5MB) 때문에 한 번에 긴 녹음을 올릴 수 없다 → 약 5분 구간(opus 32kbps 기준 약 1.2MB)으로 나눠 업로드·전사한다 (FR-14). 구간마다 `MediaRecorder`를 새로 시작해 각 구간이 독립적으로 재생 가능한 파일이 되게 한다.
- **구간 경계**: 구간을 나누는 순간 단어가 잘릴 수 있다. 1차 구현은 그대로 이어 붙이고, 품질 문제가 크면 구간 겹침 등을 추후 검토한다.
- **비용**: 60분 녹음 시 전사 12회 + 요약 1회 호출. 전사는 녹음 시간에 비례해 과금된다.
- **브라우저 지원**: `MediaRecorder` 코덱이 브라우저마다 다르다 (Chrome `webm/opus`, Safari `mp4/aac`). 지원 형식을 감지해 사용한다.
- **마이크 권한**: HTTPS 또는 `localhost`에서만 동작한다.
- **개인정보**: 녹음 음성이 OpenAI로 전송된다. 대화 중 언급된 이메일·전화번호도 포함될 수 있다. 녹음 전 안내(FR-18)로 고지한다.
- **인증 없음**: 현재 앱은 인증이 없어 배포 URL을 아는 누구나 미팅 노트를 볼 수 있다. 미팅 노트는 리드 정보보다 민감할 수 있으므로 실제 데이터 투입 전 인증 추가가 더 중요해진다.
