# 계약서·견적서 작성 (AI 대화형) 요구사항

- 작성일: 2026-11-24
- 상태: **구현 완료(1차)** — 2026-11-24, 워크트리 `worktress/aicrm-contracts`(브랜치 `feature/contracts`). 구현하면서 바뀐 내용은 12장 참고
- 와이어프레임: `docs/contracts/wireframe.html`
- 관련 화면: 헤더 메뉴(신규 `계약서`), 계약서 페이지(신규), 템플릿 편집(신규), 메일 보내기 모달(신규), 설정 Gmail 카드, 리드 상세 이력

## 1. 배경 / 목적

영업 담당자는 계약서·견적서(인보이스)를 Word 양식에서 회사명·금액·기간을 손으로 바꿔 쓰고, PDF로 저장해 메일에 따로 첨부한다.
이 과정에서 항목 누락, 이전 고객 이름이 남는 실수, 금액 계산 오류가 생긴다.

CRM 안에서:

1. 자주 쓰는 계약서·견적서를 **템플릿으로 등록**하고 바뀌는 부분을 **항목(필드)으로 표시**한다.
2. **AI Assistant가 한 번에 하나씩 질문**하고, 답할 때마다 오른쪽 문서에 바로 채워 넣는다.
3. 완성되면 **PDF로 다운로드**하거나 **내 Gmail로 고객에게 바로 발송**한다.

## 2. 결정 사항 (2026-11-24 질의응답)

| 항목 | 결정 |
|---|---|
| 문서 종류 | **계약서 + 견적서(인보이스)** 둘 다. 견적서는 품목 표(수량·단가·금액)와 합계 자동 계산이 필요 |
| 템플릿 등록 | 앱 안 편집기에 본문을 붙여넣고 바뀌는 부분을 `{{항목}}`으로 표시 + **품목 표 블록**. (docx 업로드는 제외 — 10장 Q1 확인) |
| 메일 발송 | **내 Gmail로 발송** — `gmail.send` 권한 추가. 보낸편지함에 남고 답장이 내 메일로 옴 |
| PDF | **서버에서 PDF 라이브러리 + 한글 폰트**로 생성. 다운로드와 메일 첨부가 같은 파일 |
| 리드 연결 | **리드 선택 → 회사명·담당자·이메일·금액 자동 채움**, 발송 시 리드 이력(`lead_events`)에 기록, 받는 사람 기본값 = 리드 이메일 |

## 3. 범위

| 포함 (이번 작업) | 제외 (추후 검토) |
|---|---|
| 헤더 메뉴 `계약서`, 계약서 페이지 (왼쪽 Assistant / 오른쪽 문서) | Word(.docx)·PDF 파일 업로드로 템플릿 등록 |
| 템플릿 등록·수정·복제·보관 (계약서 / 견적서) | 전자서명(모두싸인·DocuSign), 서명 상태 추적 |
| `{{항목}}` 표시 + 항목 유형·질문·필수 여부·리드 자동 채움 설정 | 고객이 웹에서 직접 열람·승인하는 링크 |
| 견적서 품목 표 + 공급가액·부가세·합계·한글 금액 자동 계산 | 다국어·다통화 문서, 환율 |
| AI가 한 번에 하나씩 질문 → 답변 해석 → 문서에 즉시 반영 | 조항 자체를 AI가 새로 작성·검토(법률 검토) |
| 문서를 클릭해 직접 수정, 대화로 이전 답변 수정 | 회사 로고·도장 이미지, 서식(글꼴·색) 편집 |
| 작성 중 문서 자동 저장, 작성한 문서 목록 | 결재(승인) 흐름 |
| PDF 다운로드, Gmail 발송(받는 사람·참조·제목·본문·첨부 확인) | 예약 발송, 수신 확인(열람 추적) |
| 발송 이력을 리드 이력에 기록 | 발송 후 리드 단계 자동 변경 (10장 Q4) |

## 4. 용어

- **템플릿(Template)**: 반복해서 쓰는 문서 양식. 종류(계약서 / 견적서), 본문, 항목 목록, 메일 제목·본문 양식으로 구성. 팀 전체 공유.
- **항목(Field)**: 템플릿에서 문서마다 바뀌는 부분. 본문에 `{{회사명}}`처럼 표시. 유형·질문 문구·필수 여부·리드 자동 채움 설정을 가진다.
- **품목 표(Line items)**: 견적서의 반복 행 표(품목·규격·수량·단가·금액). 본문에 `{{품목표}}` 블록으로 넣는다.
- **계산 항목(Computed)**: 직접 묻지 않고 다른 값에서 계산하는 항목. `{{공급가액}}`, `{{부가세}}`, `{{합계}}`, `{{합계_한글}}`(일금 일천일백만원정).
- **시스템 항목**: 자동으로 채워지는 `{{문서번호}}`, `{{작성일}}`, `{{작성자}}`, `{{작성자_이메일}}`.
- **문서(Document)**: 템플릿으로 만든 계약서·견적서 1건. 상태 `작성 중(draft)` → `완성(completed)` → `발송됨(sent)`.

## 5. 기능 요구사항

### 5.1 메뉴 / 페이지

- FR-1. 헤더 메뉴에 `계약서`(`/contracts`)를 `미팅 노트`와 `캘린더` 사이에 추가한다.
- FR-2. 계약서 페이지는 3개 영역을 가진다: 상단 탭 `새 문서` / `작성한 문서` / `템플릿`.
- FR-3. `새 문서` 화면은 **왼쪽 AI Assistant(약 40%) + 오른쪽 문서 미리보기(약 60%)** 2단 구성. 이 페이지에서는 다른 페이지의 오른쪽 AI Assistant 패널(조회형)을 숨긴다 (10장 Q3).
- FR-4. 모바일(640px 이하)에서는 2단 대신 상단 토글 `대화 / 문서`로 전환하고, 답변하면 "문서에 반영됨" 토스트와 함께 `문서` 탭에 점 표시.

### 5.2 템플릿 목록

- FR-5. 템플릿을 종류 필터(`전체 / 계약서 / 견적서`)로 보여준다. 카드: 이름, 종류 배지, 항목 수, 마지막 수정일·수정자.
- FR-6. 카드 메뉴: `수정`, `복제`, `보관`(목록에서 숨김, 이미 만든 문서는 유지). 삭제는 보관된 템플릿만, 확인 후.
- FR-7. 템플릿이 하나도 없으면 `기본 템플릿 불러오기`(샘플 계약서 1개·견적서 1개)를 제공한다.

### 5.3 템플릿 등록·수정

- FR-8. 기본 정보: 이름(필수), 종류(계약서 / 견적서, 필수), 설명.
- FR-9. 본문 편집기(텍스트): 다른 문서에서 복사해 붙여넣는다. 서식은 최소한만 지원한다.
  - `# 제목`, `## 조항 제목`, 빈 줄 = 문단, `- ` = 목록, `|---|` 없이 일반 표는 지원 안 함 (견적서 품목은 품목 표 블록 사용).
- FR-10. **바뀌는 부분 표시** — 두 가지 방법:
  - (a) 본문에서 글자를 드래그해 선택 → 떠 있는 `항목으로 지정` 버튼 → 항목 이름 입력 → 선택한 글자가 `{{항목 이름}}`으로 바뀐다. 같은 글자가 본문에 더 있으면 "3곳 모두 바꿀까요?"를 묻는다.
  - (b) `{{항목 이름}}`을 직접 입력.
  - 편집기와 미리보기에서 항목은 **색 배경 + 점선 테두리 칩**으로 표시한다 (미입력은 회색 `[회사명]`, 입력 완료는 강조색 + 실제 값).
- FR-11. 오른쪽 **항목 패널**: 본문에서 찾은 항목을 등장 순서대로 자동 목록화. 항목마다:
  - 유형: `텍스트`, `여러 줄`, `숫자`, `금액(원)`, `날짜`, `기간`, `이메일`, `전화번호`, `선택지`(보기 입력)
  - 질문 문구 (비우면 "회사명을 알려주세요" 자동), 예시·설명, 필수 여부, 기본값
  - 리드 자동 채움: `없음 / 회사명 / 담당자 / 이메일 / 전화번호 / 예상 금액`
  - 질문 순서는 드래그로 변경 (기본: 본문 등장 순서)
  - 본문에서 사라진 항목은 "본문에 없음" 표시 후 저장 시 자동 제거
- FR-12. 견적서에는 `품목 표 삽입` 버튼 → 본문 커서 위치에 `{{품목표}}` 블록. 설정: 열(품목·규격·수량·단가·금액, 규격은 끌 수 있음), 부가세(별도 10% / 포함 / 없음), 원 단위 반올림.
  - 품목 표가 있으면 계산 항목 `{{공급가액}}`, `{{부가세}}`, `{{합계}}`, `{{합계_한글}}`을 본문에 쓸 수 있다 (항목 패널에 "계산" 표시, 질문하지 않음).
- FR-13. 메일 양식: 메일 제목·본문에도 `{{항목}}`을 쓸 수 있다. 기본값
  - 제목: `[{{작성자_회사}}] {{회사명}} {{템플릿 이름}} 송부드립니다`
  - 본문: 인사 + 첨부 안내 + 서명(`{{작성자}}`, `{{작성자_이메일}}`).
- FR-14. `미리보기` 토글로 PDF와 같은 레이아웃을 확인한다. 저장 시 검증: 이름·종류 필수, 항목 이름 중복·빈 이름 불가, 선택지 유형은 보기 1개 이상, 항목 최대 50개, 본문 최대 50,000자.
- FR-15. 템플릿을 수정해도 **이미 만든 문서에는 영향 없음** — 문서는 생성 시점의 본문·항목을 복사(snapshot)해서 가진다.

### 5.4 문서 작성 — AI Assistant 대화

- FR-16. `새 문서` 진입 시 Assistant 첫 메시지: "어떤 문서를 만들까요?" + 템플릿 **버튼 목록**(종류 배지·이름, 최근 사용순, 최대 6개 + `더 보기`). 사용자가 "견적서"처럼 입력해도 된다 (이름·종류로 매칭, 여러 개면 버튼으로 다시 묻기).
- FR-17. 템플릿을 고르면 오른쪽에 문서가 표시되고(모든 항목 회색 칩) 문서가 `작성 중`으로 저장된다.
- FR-18. 다음 질문: "어느 리드의 문서인가요?" + 최근 리드 버튼(진행 중 리드, 최근 수정순 5개) + 검색 입력 + `리드 없이 작성`.
  - 리드를 고르면 리드 자동 채움 항목을 한 번에 채우고 "회사명·담당자·이메일·금액을 리드에서 채웠어요. 다른 값이 있으면 말씀해 주세요"라고 알린다.
- FR-19. **한 번에 하나씩 질문**: 아직 비어 있는 항목 중 질문 순서상 첫 항목을 묻는다. 질문 아래에 유형별 **빠른 입력**을 보여준다.
  - 선택지 → 버튼, 날짜 → `오늘`·`다음 달 1일`·날짜 선택, 기간 → `6개월`·`1년`·`2년`, 선택 항목 → `건너뛰기`.
- FR-20. 답변 처리: 답을 받으면 해당 항목 값으로 해석·정규화해 **즉시 문서에 반영**하고(칩이 강조색으로 바뀌며 해당 위치로 스크롤·깜빡임), 다음 질문을 한다.
  - 예: "다음 달 1일부터" → `2026-12-01`, "천이백만원" → `12,000,000`, "1년" → 종료일 자동 계산(종료일 항목이 있을 때).
  - 해석이 불확실하면 값을 넣지 않고 다시 묻는다 ("시작일을 날짜로 알려주세요. 예: 2026-12-01").
  - 한 답변에 여러 항목 정보가 있으면 함께 채우고 어떤 항목을 채웠는지 말한다 ("계약 시작일과 종료일을 채웠어요").
- FR-21. 견적서 품목 표: "품목을 알려주세요. 예: 'CRM 라이선스 10개 단가 5만원'"으로 묻고, 답할 때마다 행을 추가한다. `품목 추가 완료` 버튼 또는 "끝"으로 다음 항목으로. 합계는 행이 바뀔 때마다 다시 계산해 문서에 반영.
- FR-22. **수정**: 대화로 "계약 기간 2년으로 바꿔줘", "두 번째 품목 수량 20개로"처럼 고칠 수 있다. 오른쪽 문서의 칩을 클릭해 직접 입력해도 된다 (작은 입력 팝오버, Enter 저장).
- FR-23. 진행 상태: Assistant 상단에 `필수 7/9 완료` 진행 바. 문서 상단에 `미입력 2` 배지 — 클릭하면 미입력 항목으로 스크롤.
- FR-24. **완성 조건**: (a) 필수 항목이 모두 채워지면 Assistant가 "모든 항목을 채웠어요. 문서를 확인해 주세요" + `완성하기` 버튼, 또는 (b) 사용자가 "완료", "다 됐어" 등을 말하거나 `완성하기`를 누르면:
  - 필수 미입력이 있으면 "필수 항목 2개(서명일, 대표자)가 비어 있어요. 그래도 완성할까요?" → `채우기` / `빈칸으로 완성`(빈칸은 PDF에 밑줄 공백).
- FR-25. 대화·값은 자동 저장(답변마다). 페이지를 떠났다 돌아오면 `작성한 문서`에서 이어서 작성 — 대화 기록과 다음 질문이 복원된다.
- FR-26. 대화 중 범위를 벗어난 질문("이번 달 파이프라인 얼마야?")에는 "이 화면에서는 문서 작성만 도와드려요"라고 답하고 현재 질문으로 돌아간다.

### 5.5 완성 → PDF

- FR-27. 완성하면 문서가 `완성`이 되고 Assistant에 결과 카드: 문서 제목, 파일명(`견적서_에이스상사_2026-11-24.pdf`), 버튼 `PDF 다운로드` / `메일로 보내기` / `계속 수정`.
- FR-28. PDF는 서버에서 생성: A4, 한글 폰트(Noto Sans KR), 제목·조항·문단, 품목 표, 페이지 번호(`1 / 3`), 하단 문서번호. 오른쪽 미리보기와 같은 내용.
- FR-29. `계속 수정`으로 다시 `작성 중`이 될 수 있다. 발송한 문서를 수정하면 새 버전(`문서번호-v2`)으로 복제한다 (발송된 원본은 변경 불가).

### 5.6 메일 보내기

- FR-30. `메일로 보내기` → 메일 작성 모달:
  - **보낸 사람**: 내 Gmail 주소 (변경 불가, 표시만)
  - **받는 사람**: 기본값 = 리드 이메일(있으면). 사용자가 입력·수정. 여러 명(쉼표·Enter로 칩), 형식 검증. 필수
  - **참조(CC)**: 선택. 기본값 없음
  - **제목**: 템플릿 메일 양식에 값을 채운 결과. 수정 가능
  - **본문**: 템플릿 메일 양식에 값을 채운 결과. 수정 가능(여러 줄 텍스트)
  - **첨부**: PDF 칩(파일 아이콘·파일명·크기) — 클릭하면 PDF 미리보기(새 탭). 첨부 제거 불가(문서 발송이 목적), 파일명은 수정 가능
  - 버튼: `취소` / `보내기`
- FR-31. `보내기` → 확인 없이 발송(모달 안에서 이미 모든 내용을 보여줬으므로). 발송 중 버튼 비활성 + "보내는 중…".
  - 성공: 모달 닫힘, 토스트 "에이스상사(kim@ace.co.kr)에 보냈어요", 문서 상태 `발송됨`, 보낸 시각·받는 사람 기록, Assistant에 "보냈어요" 메시지 + `Gmail에서 보기` 링크.
  - 실패: 모달 유지, 에러 배너(권한 없음 / 토큰 만료 / 주소 오류 / 용량 초과) + 다시 시도.
- FR-32. Gmail 발송 권한이 없으면 `메일로 보내기` 대신 안내: "Gmail 발송 권한이 필요해요" + `설정에서 연동` (돌아오면 이 문서로 복귀). 기존 Gmail(읽기) 연동 사용자도 **1회 재연동** 필요.
- FR-33. 발송 성공 시 리드가 연결돼 있으면 같은 트랜잭션에서 `lead_events`에 `document_sent`(문서 종류·제목·받는 사람·문서 id, `user_id`) 기록. 리드 상세 이력에 "견적서 발송 — kim@ace.co.kr" 표시, 클릭 시 문서 열기.

### 5.7 작성한 문서 목록

- FR-34. 목록: 제목, 종류, 리드(회사명), 상태 배지(작성 중 / 완성 / 발송됨), 작성자, 수정일·발송일. 필터: 종류, 상태, 내 문서만. 검색: 제목·회사명.
- FR-35. 행 클릭 → `작성 중`이면 대화 화면으로 이어서, `완성`·`발송됨`이면 미리보기 + `PDF 다운로드`·`메일로 보내기`(재발송)·`복제`.
- FR-36. 삭제는 `작성 중`·`완성` 문서만, 확인 후. `발송됨`은 삭제 불가(이력 보존).

## 6. 비기능 요구사항

- **개인정보 / OpenAI 전송 범위** (기존 원칙 유지: 이메일·전화번호는 OpenAI로 보내지 않음)
  - 다음 질문 선택은 **서버 로직**(질문 순서 + 빈 항목)으로 정한다. AI는 답변 해석과 문구에만 사용.
  - OpenAI로 보내는 것: 현재 항목의 이름·유형·질문, 사용자의 마지막 답변(`maskPii` 적용), 항목 이름 목록(수정 요청 해석용). **문서 본문 전체, 다른 항목 값, 리드 이메일·전화번호는 보내지 않음.**
  - `이메일`·`전화번호` 유형 항목은 OpenAI 없이 정규식으로 해석.
  - 숫자·금액·날짜는 가능하면 서버에서 먼저 해석(예: `12,000,000`, `2026-12-01`)하고 실패할 때만 AI 사용 → 비용·지연 감소.
- **응답 속도**: 답변 → 문서 반영 2초 이내 목표. 서버 해석 성공 시 AI 호출 없이 즉시.
- **계산 정확성**: 금액은 정수(원) 계산, 부가세는 공급가액 × 10% 원 단위 반올림(설정에 따라). AI가 합계를 계산하지 않는다.
- **PDF**: 새 패키지 `pdf-lib` + `@pdf-lib/fontkit` (버전 고정, `npm audit`). 폰트 Noto Sans KR(OFL) Regular/Bold를 `web/assets/fonts/`에 포함(서버 전용, 서브셋 권장 ~2MB 이하). PDF는 저장하지 않고 값에서 매번 생성(같은 입력 → 같은 결과).
- **Gmail 발송**: Gmail REST `users.messages.send`를 `fetch`로 호출(SDK 없음), MIME multipart + base64url. 첨부 포함 메일 크기 10MB 제한. 발송 기록은 메일 본문 없이 제목·받는 사람·Gmail message id만 저장.
- **권한**: 템플릿·문서는 팀 공유(기존 원칙). 발송은 로그인한 본인 Gmail로만.
- **보안**: 모든 입력 `lib/validate.ts` 검증, SQL 파라미터 바인딩, 새 테이블 RLS + `crm_app` 정책. 메일 헤더 인젝션 방지(받는 사람·제목에 줄바꿈 금지, 주소 형식 검증).
- **접근성**: 템플릿 버튼·빠른 입력은 키보드 선택 가능, 문서 반영 시 `aria-live`로 "회사명: 에이스상사 입력됨" 안내.

## 9. 제약 / 리스크

- **Gmail 발송 권한(`gmail.send`)은 민감 범위**: 앱이 "테스트" 상태라 테스트 사용자만 사용 가능, 리프레시 토큰 7일 만료는 그대로. Google Cloud Console 동의 화면에 범위 추가 필요.
- **PDF 한글 폰트 용량**: 전체 Noto Sans KR은 수 MB → Vercel 함수 크기·콜드스타트 영향. 서브셋(KS X 1001 완성형 2,350자 + 영문·기호) 사용 시 빠지는 글자(희귀 한자·특수 문자)는 □로 표시될 수 있음.
- **서식 한계**: 텍스트 기반 템플릿이라 기존 Word 양식의 표·도장·로고·서명란 위치를 그대로 재현하지 못한다. 서명란은 텍스트(`(인)`)로 대체.
- **AI 해석 오류**: 금액·날짜를 잘못 해석할 수 있어, 채운 값을 대화에 항상 그대로 보여주고("계약 금액: 12,000,000원") 문서에서 강조한다. 발송 전 최종 확인은 사용자 책임 — 메일 모달에서 PDF 미리보기 제공.
- **법적 효력**: 이 기능은 문서 작성·발송만 하며, 전자서명·계약 체결 효력은 범위 밖.

## 12. 구현 결과 / 요구사항과 달라진 점 (2026-11-24)

- **폰트**: Noto Sans KR 대신 **나눔고딕 Regular**(OFL). pdf-lib의 폰트 subset 기능이 한글 글리프를 깨뜨려 폰트 전체를 넣는다 → PDF 약 750KB. 굵은 글씨는 같은 글자를 살짝 겹쳐 그림(Bold 폰트를 넣으면 2배 크기).
- **리드 이력 `document_sent`**: 받는 사람 **주소는 넣지 않고 수**(`recipients`)만 기록 — 이력이 AI Assistant 컨텍스트로 OpenAI에 전송되므로. 주소는 `document_sends`에만 저장. 리드 상세 화면에 이력 목록 UI는 없어 Assistant 질문("에이스상사 견적서 언제 보냈어?")으로 확인.
- **AI로 보내는 품목 정보**: 품목 수정("두 번째 품목 수량 20개로") 해석을 위해 품목명·규격·수량·단가는 보낸다 (개인정보 아님).
- **질문 순서**: 견적서는 리드 다음에 품목을 먼저 묻고, 그 다음 항목을 묻는다 (품목 표 위치와 무관).
- **기본값**: 항목의 기본값은 자동으로 채우지 않고 첫 번째 빠른 답변 버튼으로 보여준다.
- **종료일 자동 계산**: 기간 유형 항목 + 이름에 '시작'·'종료(만료)'가 들어간 날짜 항목이 있을 때. 시작일·기간이 바뀌면 다시 계산.
- **새 패키지**: `pdf-lib@1.17.1`, `@pdf-lib/fontkit@1.1.1` (exact, npm audit 0).
- **e2e 포트**: `E2E_PORT` 환경 변수 추가 (기본 3100) — 다른 워크트리와 동시 실행용.
- **테스트**: unit `test/unit/docTemplate.test.ts`(해석·계산·MIME), integration `test/integration/documents.test.ts`(대화 흐름·AI 전송 범위·PDF·발송·이력·단계 이동), e2e `e2e/contracts.spec.ts` + `mobile.spec.ts`.
