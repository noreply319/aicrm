# 회사(Company) 관리 + 리드 회사 선택 요구사항 / 구현 계획

- 작성일: 2026-11-24
- 상태: **구현 중** — 2026-11-24 1·2차 질의응답 반영 (2장, 11장). 구현하면서 바꾼 점은 13장
- 와이어프레임: `docs/companies/wireframe.html`
- 관련 화면: 헤더 메뉴(신규 `회사`), 회사 목록(신규), 회사 상세(신규), 회사 등록·수정 모달(신규), 리드 모달 `회사명` 입력란(변경)

## 1. 배경 / 목적

지금은 리드마다 회사명을 텍스트로 직접 입력한다. 그래서

- 같은 회사가 `에이스상사` / `(주)에이스상사` / `에이스 상사`처럼 여러 이름으로 흩어지고,
- 한 회사에 리드가 여러 건이어도 회사 단위 금액·진행 상황을 볼 수 없고,
- 업종·규모·사업자번호 같은 회사 정보를 저장할 곳이 없다.

이번 작업으로:

1. 상단 메뉴 `회사`에서 **회사를 등록·수정·조회**하고, 회사별 연결 리드와 금액을 본다.
2. 리드를 등록·수정할 때 회사명을 **검색 + 드롭다운으로 선택**한다.
3. 검색 결과에 없으면 드롭다운의 **`+ "○○" 새 회사로 생성`** 버튼으로 이름만 넣어 바로 만들고 선택한다.

## 2. 결정 사항 (2026-11-24 질의응답)

| 항목 | 결정 |
|---|---|
| 회사 항목 | 회사명(필수) + **기본 정보**(웹사이트, 업종, 규모, 대표 전화, 주소, 메모) + **사업자 정보**(사업자등록번호, 대표자명) + **영업 관리 정보**(담당 영업, 등급, 태그) + **이메일 도메인** |
| 기존 데이터 | 마이그레이션 때 리드의 회사명으로 **회사를 자동 생성하고 연결**. 공백·대소문자를 정리한 이름이 같으면 같은 회사 |
| 회사 화면 | **목록 + 상세**. 상세에서 회사 정보 수정, 연결된 리드 목록, 이 회사로 리드 추가 |
| 리드에서 바로 생성 | 검색어(회사명)만으로 **즉시 생성·선택**. 상세 정보는 나중에 회사 메뉴에서 보완 |

## 4. 용어

- **회사(Company)**: 영업 대상 조직. 리드 여러 건을 가질 수 있다. 팀 전체 공유.
- **연결 리드**: `leads.company_id`가 이 회사인 리드.
- **회사 파이프라인**: 연결 리드 중 `won`·`lost`를 제외한 금액 합계. **수주 금액**: `won` 리드 금액 합계.
- **담당 영업(Owner)**: 이 회사를 맡은 팀원(`users`). 비어 있을 수 있다.
- **등급(Tier)**: `A` / `B` / `C` (회사 중요도). 리드 우선순위(`high/mid/low`)와는 별개.
- **이메일 도메인**: 회사 메일 도메인(`acme.co.kr`). 무료 메일 도메인은 저장 불가.

## 5. 기능 요구사항

### 5.1 메뉴

- FR-1. 헤더 메뉴에 `회사`(`/companies`)를 `파이프라인` 바로 다음에 추가한다. (`파이프라인 · 회사 · 미팅 노트 · 캘린더 · 설정`)
- FR-2. 회사 화면에서 헤더의 추가 버튼은 `회사 등록`, 검색 placeholder는 `회사명, 업종, 도메인, 태그 검색…`.
- FR-3. `(crm)` 경로 그룹 안에 `companies/page.tsx`, `companies/[id]/page.tsx`(빈 page)를 두고 `CrmApp`의 `viewOf()`에 `companies`를 추가한다. 회사 목록은 레이아웃 상태로 유지돼 메뉴 이동 시 다시 불러오지 않는다.

### 5.2 회사 목록

- FR-4. 표 형태(데스크톱): 회사명(+도메인), 업종, 규모, 담당 영업, 등급, 태그, **진행 리드 수**, **파이프라인 금액**, **수주 금액**, 최근 리드 변경일.
- FR-5. 검색: 회사명·업종·도메인·태그 (헤더 검색창, 대소문자·공백 무시).
- FR-6. 필터: `내 담당만`, 등급(A/B/C), 업종, `진행 리드 있음`. 정렬: 이름순 / 파이프라인 금액순(기본) / 최근 변경순.
- FR-7. 행 클릭 → 회사 상세. 빈 상태: "등록된 회사가 없어요" + `회사 등록` 버튼.
- FR-8. 모바일(640px 이하)은 표 대신 카드 목록(회사명, 업종·규모, 리드 수·파이프라인 금액).

### 5.3 회사 등록·수정 모달

- FR-9. 섹션: **기본 정보** / **사업자 정보** / **영업 관리** / **메모**.

  | 항목 | 입력 | 검증 |
  |---|---|---|
  | 회사명 * | 텍스트 | 1~100자, 같은 정규화 이름 중복 불가 (FR-12) |
  | 웹사이트 | URL | `http(s)://` 없으면 자동으로 `https://` 붙임, 500자 |
  | 이메일 도메인 | 텍스트 | 도메인 형식, 소문자 저장, `FREE_MAIL_DOMAINS` 불가, 다른 회사와 중복 불가. 웹사이트 입력 시 도메인 자동 제안 |
  | 업종 | 텍스트 + 기존 값 자동완성(datalist) | 50자 |
  | 규모 | 선택: `1-10` / `11-50` / `51-200` / `201-1000` / `1000+` / 미정 | 목록 값만 |
  | 대표 전화 | 텍스트 | 30자 |
  | 주소 | 텍스트 | 300자 |
  | 사업자등록번호 | `000-00-00000` | 숫자 10자리, 하이픈 자동, 체크섬은 경고만(저장 허용) |
  | 대표자명 | 텍스트 | 50자 |
  | 담당 영업 | 팀원 선택(로그인 사용자 목록), 기본값 없음 | `users.id` |
  | 등급 | `A` / `B` / `C` / 없음 | 목록 값만 |
  | 태그 | 칩 입력(Enter로 추가), 기존 태그 자동완성 | 최대 10개, 각 20자 |
  | 메모 | 여러 줄 | 5000자 |

- FR-10. 저장 시 낙관적 업데이트 → 실패 시 `reload()` + 에러 배너 (기존 패턴).
- FR-11. 삭제: 연결 리드가 있으면 **삭제 불가**(버튼 비활성 + "연결된 리드 N건이 있어 삭제할 수 없어요. 리드를 다른 회사로 옮기거나 삭제해 주세요"). 연결 리드가 없으면 확인 후 삭제.
- FR-12. 중복 판단: 이름을 **정규화**(공백 모두 제거, 소문자, `(주)`·`주식회사`·`㈜` 제거 후 비교)한 값이 같으면 중복. 저장 시 409 + "이미 등록된 회사예요: (주)에이스상사" + `그 회사로 이동` 링크.

### 5.4 회사 상세 (`/companies/[id]`)

- FR-13. 상단: 회사명, 등급 배지, 태그, 웹사이트 링크, `수정` 버튼.
- FR-14. 요약 카드: 진행 리드 수, 파이프라인 금액, 수주 금액, 실주 건수.
- FR-15. 왼쪽 회사 정보(읽기, 빈 항목은 `—`), 오른쪽 **연결 리드 목록**: 단계 배지·담당자·금액·마감일, 진행 중 → 수주/실주 순. 클릭하면 기존 리드 모달.
- FR-16. `+ 이 회사로 리드 추가` → 리드 모달을 회사가 선택된 상태로 연다.
- FR-17. 없는 id·잘못된 id → "회사를 찾을 수 없어요" + 목록으로 이동 링크.

### 5.5 리드 모달 — 회사 검색·선택 (콤보박스)

- FR-18. 기존 `회사명 *` 텍스트 입력을 **회사 콤보박스**로 바꾼다. 필수.
- FR-19. 입력하면 회사 목록(클라이언트에 이미 로드됨)에서 즉시 필터: 정규화 이름 **부분 일치**, 초성 검색은 이번 범위 제외. 결과 최대 8개, 일치 부분 굵게, 각 항목에 업종·진행 리드 수 표시.
- FR-20. 드롭다운 맨 아래 항상 **`+ "입력값" 새 회사로 생성`**. 정규화 이름이 완전히 같은 회사가 있으면 이 버튼 대신 그 회사를 맨 위에 "일치" 표시.
- FR-21. `새 회사로 생성` 클릭(또는 결과 없을 때 Enter) → `POST /api/companies { name }` 즉시 호출 → 성공하면 선택 상태가 되고 토스트 "회사 '○○'를 만들었어요. 상세 정보는 회사 메뉴에서 입력할 수 있어요". 리드 모달은 닫히지 않고 입력 중인 값도 그대로 유지한다.
  - 리드를 저장하지 않고 취소해도 만든 회사는 남는다 (빈 회사는 목록에서 `연결 리드 0`으로 보임).
- FR-22. 선택된 상태: 입력란 대신 **선택 칩** `🏢 에이스상사 · 제조 ✕`. ✕ 또는 클릭하면 다시 검색 모드.
- FR-23. 키보드: ↑/↓ 이동, Enter 선택, Esc 닫기, Tab은 현재 강조 항목 선택하지 않고 이동. ARIA `combobox` / `listbox` / `option` 패턴.
- FR-24. **이메일 도메인 추천**: 회사가 아직 선택되지 않았는데 리드 이메일을 입력하면 도메인이 같은 회사가 있을 때 콤보박스 아래 "이메일 도메인이 같은 회사: 에이스상사 [선택]" 힌트.
- FR-25. 리드 상세(수정) 모달에서는 회사 칩 옆 `회사 정보 →` 링크로 회사 상세 이동.

- FR-29. ~~(이번엔 보류, 13장)~~ Gmail `leadTarget()`: 리드에 연결된 회사의 `email_domain`이 있으면 리드 이메일 도메인 대신 그 도메인으로 회사 메일을 검색한다 (리드 이메일 도메인이 회사 도메인과 다를 때 대비).

## 6. 비기능 요구사항

- **성능**: 회사 목록은 리드처럼 첫 로드에 전체를 받는다(예상 수백~수천 건). 리드 수·금액은 SQL 집계로 함께 내려준다. 2,000건 초과 시 서버 검색으로 전환 검토.
- **동시성**: 같은 이름 동시 생성 → DB 유니크 인덱스(`name_key`)로 막고, 409면 기존 회사를 받아 그 회사를 선택 (사용자에게 에러 대신 "이미 있는 회사를 선택했어요").
- **접근성**: 콤보박스 ARIA 패턴, 결과 수 `aria-live` 안내("3개 회사 검색됨").
- **스타일**: `globals.css` 기존 토큰만 사용. 등급 배지는 기존 `--prio-*` 계열 재사용 검토, 새 토큰이 필요하면 라이트/다크 모두 정의.

## 7. 데이터 모델 (안)

**설계 방향**: `leads.company`(텍스트)는 **회사명 사본으로 유지**하고 `leads.company_id`를 추가한다.
회사명을 쓰는 곳(이력, Assistant, 미팅 노트, 캘린더, Gmail, 계약서)이 많아 JOIN으로 바꾸면 변경 범위가 커지기 때문. 회사명 변경 시 사본을 같은 트랜잭션에서 갱신한다(FR-27).

```sql
CREATE TABLE IF NOT EXISTS companies (
  id               uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  name             text NOT NULL CHECK (length(trim(name)) BETWEEN 1 AND 100),
  name_key         text NOT NULL,               -- 정규화 이름 (중복 판단용, 서버에서 계산)
  website          text NOT NULL DEFAULT '',
  email_domain     text,                        -- 소문자, NULL 허용 (중복 불가)
  industry         text NOT NULL DEFAULT '',
  size             text CHECK (size IN ('1-10','11-50','51-200','201-1000','1000+')),
  phone            text NOT NULL DEFAULT '',
  address          text NOT NULL DEFAULT '',
  business_number  text NOT NULL DEFAULT '',     -- 숫자 10자리 (표시할 때 하이픈)
  ceo_name         text NOT NULL DEFAULT '',
  owner_id         uuid REFERENCES users(id) ON DELETE SET NULL,
  tier             text CHECK (tier IN ('A','B','C')),
  tags             text[] NOT NULL DEFAULT '{}',
  notes            text NOT NULL DEFAULT '' CHECK (length(notes) <= 5000),
  created_by       uuid REFERENCES users(id) ON DELETE SET NULL,
  created_at       timestamptz NOT NULL DEFAULT now(),
  updated_at       timestamptz NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX IF NOT EXISTS companies_name_key_idx ON companies (name_key);
CREATE UNIQUE INDEX IF NOT EXISTS companies_email_domain_idx ON companies (email_domain) WHERE email_domain IS NOT NULL;
ALTER TABLE companies ENABLE ROW LEVEL SECURITY;
-- crm_app 전용 정책 (lead_events와 같은 DO $$ 블록 패턴)

ALTER TABLE leads ADD COLUMN IF NOT EXISTS company_id uuid REFERENCES companies(id) ON DELETE RESTRICT;
CREATE INDEX IF NOT EXISTS leads_company_idx ON leads (company_id);
```

- **마이그레이션**(schema.sql 끝, 재실행 안전):
  1. `company_id IS NULL`인 리드의 회사명을 정규화해 그룹화 → 그룹마다 `companies` 1건 생성(이름은 그 그룹에서 가장 먼저 만든 리드의 원래 표기) — `ON CONFLICT (name_key) DO NOTHING`.
  2. ~~이메일 도메인 자동 채움~~ — 하지 않음 (13장).
  3. `UPDATE leads SET company_id = c.id FROM companies c WHERE company_id IS NULL AND c.name_key = 정규화(leads.company)`.
  4. 정규화 함수는 SQL 함수 `crm_company_key(text)`로 만들어 마이그레이션과 서버(`lib/companies.ts`)가 같은 규칙을 쓰게 한다 (서버는 INSERT 시 `crm_company_key($1)` 호출).
  5. 모든 리드가 연결된 뒤 `leads.company_id`를 `NOT NULL`로 바꾸는 것은 **2단계**(배포 후 미연결 0건 확인 뒤).
- **`lead_events`**: 새 타입 없음. 리드의 회사 변경·회사명 변경은 `updated` + `{ company: {from, to} }`. 회사 자체 변경 이력(`company_events`)은 이번 범위 제외.
- **타입**(`lib/types.ts`): `Company`, `CompanyInput`, `CompanySummary`(목록용: `openLeads`, `pipelineValue`, `wonValue`, `lastLeadAt`), `Lead`에 `companyId: string | null`.
- **상수**(`lib/constants.ts`): `COMPANY_SIZES`, `COMPANY_TIERS`, `COMPANY_TAG_MAX` 등. 바꾸면 schema CHECK도 함께.

## 8. API (안)

모두 `proxy.ts`로 자동 보호, 입력은 `lib/validate.ts`(`validateCompanyInput`), id는 `UUID_RE`.

| 메서드 · 경로 | 설명 | 응답 |
|---|---|---|
| `GET /api/companies` | 전체 목록 + 리드 집계 | `CompanySummary[]` |
| `POST /api/companies` | 생성. `{ name }`만 보내도 됨(바로 생성) | `201 Company` / `409 { error, company }`(기존 회사 포함) |
| `GET /api/companies/[id]` | 상세 | `Company` / 404 |
| `PATCH /api/companies/[id]` | 수정. 이름 변경 시 연결 리드 `company` 갱신 + 이력 (트랜잭션) | `Company` / 409 |
| `DELETE /api/companies/[id]` | 연결 리드 있으면 409 | `{ ok: true }` |
| `POST /api/leads`, `PATCH /api/leads/[id]` | **변경**: `companyId`로 회사 지정 → `company` 텍스트는 서버가 회사명으로 채움(클라이언트 값 무시). `companyId` 없이 `company`만 오면 같은 정규화 이름의 회사를 찾거나 만들어 연결 (13장) | 기존 |

- 서버: `lib/companies.ts`(컬럼 매핑, 집계 SQL, 이름 변경 전파). 클라이언트: `lib/useCompanies.ts`(목록·생성·수정·삭제, 낙관적 업데이트) — 리드 변경 후 회사 집계도 갱신(리드 저장·이동·삭제 시 `useCompanies.reload()` 또는 클라이언트에서 집계 계산 — 집계는 클라이언트 `leads`로 계산하는 쪽을 권장, 추가 요청 없음).
- 컴포넌트: `CompanyList`, `CompanyDetail`, `CompanyModal`, `CompanyCombobox`(리드 모달에서 사용).

## 9. 구현 순서

1. **DB**: `schema.sql`에 `companies`, `crm_company_key()`, `leads.company_id`, RLS, 마이그레이션 → 로컬 `npm run db:init`로 확인, `seed.sql`에 샘플 회사 추가.
2. **서버**: `lib/companies.ts`, `validate.ts`, `/api/companies` Route Handler, 리드 API의 `companyId` 처리 + 이름 변경 전파.
3. **클라이언트 데이터**: `types.ts`, `useCompanies.ts`, `useLeads`에 `companyId` 반영.
4. **리드 모달 콤보박스** (`CompanyCombobox`) — 사용자 가치가 가장 큰 부분 먼저.
5. **회사 메뉴**: Header NAV, `viewOf`, 목록·상세·모달.
6. **연동**: Gmail `leadTarget` 회사 도메인, Assistant 컨텍스트.
7. **테스트**
   - unit: `crm_company_key`와 같은 규칙의 정규화 함수, 사업자번호 형식, 도메인 검증.
   - integration: 회사 CRUD, 중복 409, 연결 리드 있는 회사 삭제 409, 이름 변경 → 리드 `company` 갱신 + `lead_events` 기록, 리드 생성 시 `companyId` 필수, 마이그레이션(텍스트만 있는 리드 → 회사 생성·연결, 재실행 안전).
   - e2e: 리드 모달에서 검색 → 선택 → 저장 / 없는 회사 바로 생성 → 저장 / 회사 메뉴 등록 → 상세 → 이 회사로 리드 추가.
8. `npm run build` + `npm test` + `npm run test:e2e`.
9. **배포**: Supabase에 `schema.sql` 실행(쓰기 작업 — 실행 전 사용자 확인) → 운영 데이터로 마이그레이션 결과(회사 수, 미연결 리드 0건) `--read-only`로 확인.

## 10. 제약 / 리스크

- **자동 마이그레이션 중복**: `에이스상사`와 `에이스 산업`처럼 정규화로도 못 잡는 중복은 그대로 두 회사가 된다 → 리드를 다른 회사로 옮기고 빈 회사를 삭제해 수동 정리 (병합 기능은 추후).
- **운영 DB 변경**: `leads` 컬럼 추가 + 데이터 갱신. Vercel 배포 전에 Supabase 스키마를 먼저 적용해야 새 코드가 동작(구 코드는 `company_id`를 안 쓰므로 먼저 적용해도 안전).
- **`ON DELETE RESTRICT`**: 리드가 있는 회사는 DB 차원에서 삭제 불가 — 의도된 동작.
- **계약서 기능과 겹침**: 계약서 리드 자동 채움에 사업자번호·대표자 항목을 나중에 추가 가능.
